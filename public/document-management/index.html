Document Management

Here are some strategies for you to manage and improve your documents.

How to manage mountains of feedback

Managing feedback on documentation can be time-consuming, and it always takes time away from documenting new product functionality. If you can’t hire more writers, you can try these strategies:

  • Tag feedback based on the effort needed so writers can tackle quick fixes during breaks from complex tasks. Schedule bigger tasks along with regular work.
  • Set aside dedicated time each month or quarter for a “bug bash” focused only on fixing documentation issues.
  • Have customer-facing teams help filter feedback for high-quality requests, and redirect product-related issues to other teams.
  • Use a knowledge base to answer common questions and create standard replies to reduce repetitive feedback handling.
  • Not all feedback is worth addressing, especially if it takes time away from writing valuable new content.

Using callouts/admonitions in tech docs

When writing technical documentation, using callouts or admonitions (like boxes that highlight information) can help make content clearer, but overusing them can overwhelm readers. Different types of callouts serve specific purposes:

  • Tip: Helpful advice that isn’t critical.
  • Note: Relevant but non-essential information that adds context but doesn’t affect the task’s outcome.
  • Important: Details that, if missed, could cause extra work.
  • Warning: Critical information about risks, like data loss.

Use these sparingly to avoid “admonition fatigue.” If something is crucial, make it stand out, but less important details can be included in the main text for better flow. The goal is to guide users without overwhelming them.
